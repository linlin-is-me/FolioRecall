| NanoVDR-Q-DistilBERT-Qwen3VL2B-2048-ML | `ab3f0fde9fcf407eaa756e1fc349ac09b7a716e7` | `configs/student-ml-{cpu,cuda}.json` |

发布包采用6层DistilBERT、mean pooling、768→768 GELU→2048 Identity投影及Normalize，输入原文、最长512 tokens，使用配套uncased tokenizer。输出转float32后再次归一化，以匹配现有FAISS内积索引。固定包的骨干为safetensors，两层投影原文件为pytorch_model.bin；下载脚本同时保留。实测每包68,528,384参数、权重文件274,128,506 bytes，CPU对照官方encode的最大绝对差为英文1.02e-7、ML 6.71e-8。

上游来源：[英文发布包](https://huggingface.co/nanovdr/NanoVDR-Q-DistilBERT-Qwen3VL2B-2048/tree/ae406c843794bb237a6406b1143ca1a14ec7cb1f)、[ML发布包](https://huggingface.co/nanovdr/NanoVDR-Q-DistilBERT-Qwen3VL2B-2048-ML/tree/ab3f0fde9fcf407eaa756e1fc349ac09b7a716e7)，许可均为Apache-2.0。当前作者仓库主线已转向8B/4096配置，不能直接套用其最新训练脚本替代这两个发布包；本项目复用发布模型、STTrainer和余弦对齐思路，自行适配数据绑定、检查点评测与成本记录。

NanoVDR原训练教师查询指令为 `Find a document image that matches the given query.`，本项目教师使用 `Represent the user's input.`。学生仍直接输入查询，不拼接任一教师指令；本项目蒸馏使用所选教师的现有配置。上游实际2B建库revision与像素覆盖参数未完整核实，因此结果仅代表本项目页面预处理条件，不宣称复现作者建库。公开学生训练包含VDR英文来源，具体样本重叠未核实。[论文附录B与I.2](https://arxiv.org/html/2603.12824v2)

## 独立查询与测量

`query/evaluate --config`始终描述页面教师；`--query-config`描述学生及本项目允许匹配的教师身份。省略学生配置时保留原教师路径。身份错配在模型加载前报错；本地学生包还核对自身保存的身份，不能仅改模型路径绕过匹配检查。

```bash
source scripts/activate_env.sh
# 已完成下载；通常直接复用缓存，不必重复执行。
python scripts/prepare_students.py
# 已验证CPU入口；不会加载教师权重。
CUDA_VISIBLE_DEVICES= HF_HUB_OFFLINE=1 python -m foliorecall query \
  --config configs/baseline.json --query-config configs/student-ml-cpu.json \
  --index indexes/vdr-dev-original 'How did El Niño in 1998 affect Okinawa reefs?' --json
```

完整评测使用 `evaluate --benchmark`：固定200查询与1000页候选库，单请求batch1，PyTorch线程4、FAISS线程1，预热5次并重复3轮。独立进程每次只加载一款查询模型。结果记录编码、编码加搜索和文本输入至JSON就绪的本地请求P50/P95，保留逐请求时间；质量指标计算在计时之外。GPU计时在开始前和编码结束后同步。

进程启动与模型加载不属于常驻请求延迟；加载时间单列，任务进程完整墙钟时间在预算账本单列。RSS是整个Python进程内存，峰值含此前模型加载，读取到评测结束；CUDA allocated/reserved峰值另列。GPU教师与GPU学生使用BF16进行同硬件比较；CPU学生使用FP32，只作为另一种部署配置，不与历史GPU数字拼接计算算法加速比。结果JSON与CLI共用同一查询处理函数，不包含HTTP传输、页面图像或界面渲染。

## 退化诊断与停止依据

第94步相对GPU ML初始化2条改善、14条退化、184条不变，nDCG差-0.019227，不满足扩量所需+0.001门槛，因此无需启动扩量耗时估算或10000条训练。该检查点相对GPU教师3条改善、14条退化、183条不变，nDCG差-0.015764。全部开发标签不变。

教师身份、查询ID/文本与目标行序已绑定并通过检查。学生始终输入原文，配套tokenizer、mean pooling、两层投影及Normalize完整保存；CPU FP32和GPU BF16都观察到退化，不能归咎于BF16单一路径。3000训练查询与200开发查询无规范化文本重叠，最大token长度130/32，无512-token截断。原3000条属于同一来源的训练页面池，主题覆盖、原始文档隔离和上游训练样本重叠仍未充分核实。

在训练前64条上，与教师的平均余弦从0.727升到0.898；独立开发200条从0.729升到0.896。开发目标只存到 `outputs/stage3/alignment-teacher`，从未进入训练缓存。对齐在开发查询上也改善，但页面排序下降；本轮证据支持对齐损失不足以保留既有排序优势，不能唯一归因于数据规模或某项预处理。相关产物在 `alignment-{teacher,initialization,trained}`。

最大变化5例见 `short-selection/review-notes.json`：机器人表单原标命中改善，冲绳事件、D0公式与VOL-171编号退化，零工工作替代页面可能也是相关页。复用此前三对页面的视觉记录，本轮另查两对新页面。均为助手观察，不是人工补标。已有公开学生可用，当前没有依据追加教师实验或强行保留本轮蒸馏权重。

## 已运行入口与恢复方式

`scripts/run_stage3_task.py`顺序执行命令、保存日志并累计8小时模型进程墙钟时间；下载、元数据处理和合成单元测试属于准备工作，不计入模型任务账本。它使用独占锁，已有活动记录时拒绝重入，失败保留日志与耗时，重试使用新任务名。每次恢复先核对 `outputs/stage3/budget.json`，不能清空账本重新获得8小时。

先完成公开GPU基线和教师统一协议测量，每组各执行一次：

```bash
# 以下输出已经存在；复跑必须改用新任务名与新输出目录。
python scripts/run_stage3_task.py public-en-cuda -- python -u -m foliorecall evaluate \
  --config configs/baseline.json --query-config configs/student-en-cuda.json \
  --index indexes/vdr-dev-original --data data/vdr-stage2/dev \
  --output outputs/stage3/public-en-cuda --benchmark
# ML组替换en为ml，教师组省略--query-config，任务名与输出目录使用teacher-cuda。
python -m scripts.analyze_student_baselines --names public-en-cuda public-ml-cuda \
  --output outputs/stage3/gpu-comparison
```

比较脚本保留原标签和现有完整候选库，按GPU nDCG@10、Recall@10、Recall@5选初始化，完全相同优先ML。该选择只用于训练起点，不更改默认部署。后续蒸馏命令中的 `SELECTED_QUERY_CONFIG` 必须取GPU比较结果对应的配置。

```bash
# 首次只生成64条，清单预先绑定全部3000条，后续同目录补缺块。
python scripts/run_stage3_task.py targets-first64 -- python -u -m foliorecall cache-teacher \
  --output outputs/stage3/targets-3000 --count 3000 --stop-after 64
python scripts/run_stage3_task.py distill-smoke-v3 -- python -u -m foliorecall distill \
  --query-config "$SELECTED_QUERY_CONFIG" --targets outputs/stage3/targets-3000 \
  --output outputs/stage3/distill-smoke-v3 --limit 64 --max-steps 4 --skip-evaluation
python scripts/run_stage3_task.py targets-rest -- python -u -m foliorecall cache-teacher \
  --output outputs/stage3/targets-3000 --count 3000
python scripts/run_stage3_task.py distill-3000 -- python -u -m foliorecall distill \
  --query-config "$SELECTED_QUERY_CONFIG" --targets outputs/stage3/targets-3000 \
  --output outputs/stage3/distill-3000 --max-seconds 21600
```

64条验证与正式训练分开。正式短跑重新加载选定公开初始化，3 epochs、seed42、lr1e-5、AdamW weight decay0.01、线性调度与3%warmup、有效batch32、BF16 autocast及FP32主权重、梯度裁剪1.0。实测微批32，无OOM，未启用16/8回退。首步学习率为0，与warmup一致；不按单步损失选择模型。

每个epoch保存完整ST包，再用独立BF16查询进程评测原教师页面库；此时训练进程暂停但仍驻留，结果只用于质量选模，不用作部署内存基准。预算不足时只保存并标记待评测。`--resume <所属输出目录/checkpoint-N>`要求相同训练配置、目标清单和所属输出目录；允许调整本次运行时限。仅对未完成运行使用恢复，不回退到已有后续产物的旧检查点。本次全部完成，无待恢复训练；CPU小模型已验证底层Trainer恢复，真实GPU学生优化器恢复未追加复跑。

```bash
# 未来某次未完成运行的恢复模板，RUN_OUTPUT和CHECKPOINT取该次实际位置。
python scripts/run_stage3_task.py new-resume-name -- python -u -m foliorecall distill \
  --query-config configs/student-ml-cuda.json --targets outputs/stage3/targets-3000 \
  --output "$RUN_OUTPUT" --resume "$RUN_OUTPUT/$CHECKPOINT" --max-seconds 3600
```

公开初始化、各epoch均为候选，nDCG、Recall@10、Recall@5依次比较，同分保留较早状态。只有短跑nDCG较初始化提高至少0.001且Recall@10不降，才考虑扩到总计10000查询。扩量保留原3000条，重建全量seed42页面切分并排除规范化重复查询组，从训练侧补7000条，不下载页面。新目标目录采用 `--count 10000`；从相同公开初始化再训3 epochs，记录数据量和训练计算量同时变化。预计投入加25%余量仍需留出30分钟收尾评测，否则停止扩大。
