### 源码与环境

从公开仓库克隆，在同一个Bash终端设置后续命令使用的路径。以下CPU环境支持数据准备、BM25及已有索引的学生查询，不会自动生成页面库。

```bash
git clone https://github.com/linlin-is-me/FolioRecall.git
cd FolioRecall
REPO=$(pwd -P)
WORK="$REPO/outputs/reproduction"
mkdir -p "$WORK"
python3.10 -m venv .venv-cpu
CPU_PY="$REPO/.venv-cpu/bin/python"
"$CPU_PY" -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
"$CPU_PY" -m pip install '.[demo,eval]'
"$CPU_PY" -m pip check
CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall --help
```

仅在需要GPU页面建库、教师查询或训练时安装以下独立环境：

```bash
python3.10 -m venv .venv-gpu
GPU_PY="$REPO/.venv-gpu/bin/python"
"$GPU_PY" -m pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu126
"$GPU_PY" -m pip install '.[demo,image,train,eval]'
"$GPU_PY" -m pip check
```

CPU和GPU使用不同解释器。首次加载原始教师或公开学生时，按配置中的固定revision下载完整上游模型；缓存完整后可启用 `HF_HUB_OFFLINE=1`。既有验证平台为Python3.10、Ubuntu22.04／WSL、RTX4060 Laptop 8GB，其他平台未实测。GPU PDF流程需要教师权重和自行生成的页面索引；42页CPU演示另需待发布的示例包，见[示例包使用步骤](#42页-cpu-示例待release发布)。

### GPU自有PDF

以下沿用上述 `REPO`、`WORK`、`GPU_PY`、`CPU_PY`，将PDF变量改为自己的真实文件。模型、分辨率和精度沿用已验证配置；教师权重与GPU建库成本独立于CPU学生体验。

```bash
PDF="$HOME/Documents/report.pdf"
"$GPU_PY" -m foliorecall import "$PDF" --output "$WORK/my-pages"
"$GPU_PY" -m foliorecall index --config "$REPO/configs/baseline.json" \
  --pages "$WORK/my-pages/pages.jsonl" --output "$WORK/my-index" --chunk-size 64
"$GPU_PY" -m foliorecall query --config "$REPO/configs/baseline.json" \
  --query-config "$REPO/configs/student-ml-cuda.json" --index "$WORK/my-index" \
  'What are the main findings of this report?' --json
"$GPU_PY" -m foliorecall serve --config "$REPO/configs/baseline.json" \
  --query-config "$REPO/configs/student-ml-cuda.json" --index "$WORK/my-index"
# 停止GPU服务后，同一原始教师索引可以改用CPU ML查询。
CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall query --config "$REPO/configs/baseline.json" \
  --query-config "$REPO/configs/student-ml-cpu.json" --index "$WORK/my-index" \
  'What are the main findings of this report?' --json
```

达到 `index --max-seconds` 时保存当前块并以75退出，使用相同页面清单、配置、输出加 `--resume` 接续。已有完整输出拒绝覆盖，输入或配置变化需用新目录。页面或适配器路径属于现有兼容检查的一部分，不直接改写历史索引配置。

### 五域正式评测

从源码根目录执行。数据准备不加载模型；省略 `--training-data` 明确记录交集未检查。已有正式结果的空交集是当时执行检查的证据，不自动继承给新运行。若已有本轮训练切分，显式加 `--training-data /实际切分目录`。重复准备复用页面数据，并在该任务的runs目录保存本次交集检查。

新的神经检索与BM25评测会关联该任务最新一次交集检查及其记录位置，包括明确的 `not_checked` 状态；后一次未检查不会沿用更早的空交集。`source.json`仍保存原始数据准备记录，已有评测结果不改写，也不为更新交集说明重算指标。只有历史记录的旧任务按其可用证据标明来源，不将缺失检查当作已检查。

```bash
cd "$REPO"
CUDA_VISIBLE_DEVICES= "$CPU_PY" scripts/prepare_stage4_data.py \
  --config configs/stage4-evaluation.json --output "$WORK/data"
for task in hr computer_science pharmaceuticals finance_en industrial; do
  CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall evaluate-text \
    --config "$REPO/configs/stage4-evaluation.json" --data "$WORK/data/$task" \
    --output "$WORK/results/$task/bm25"
done
```

先运行原始教师和公开EN／ML的完整五域比较。包含HR原始库首次建库，使用完整候选任务；循环串行执行，CPU评测不与GPU任务并行。这一组不依赖本项目待发布附件。

```bash
for task in hr computer_science pharmaceuticals finance_en industrial; do
  "$GPU_PY" -m foliorecall index --config "$REPO/configs/baseline.json" \

    --index "$WORK/indexes/$task/original" --data "$WORK/data/$task" --output "$WORK/results/$task/gpu-original"

      --query-config "$REPO/configs/student-$student-cuda.json" --index "$WORK/indexes/$task/original" \
      --data "$WORK/data/$task" --output "$WORK/results/$task/gpu-$student"
    CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall evaluate --benchmark --config "$REPO/configs/baseline.json" \
      --query-config "$REPO/configs/student-$student-cpu.json" --index "$WORK/indexes/$task/original" \
      --data "$WORK/data/$task" --output "$WORK/results/$task/cpu-$student"

```

对照复用 `train --checkpoint-only`，两组均完成64步及独立加载后的完整开发评测，第32／64步检查点均保存。第32步224个适配器张量逐位一致，最终224个张量均有差异，确认干预生效。64步适配器只用于方法诊断，不作为教师候选。记录的模型任务耗时约79.4分钟（具体统计边界见对照记录），低于4小时预算，计算进程已完成。数据及批次在 `data/vdr-stage2-control`，运行状态、命令与日志在 `outputs/stage2/negative-control`。已有输出不能直接覆盖。
