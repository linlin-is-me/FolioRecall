# 首版使用与评测

第四阶段首轮仅执行非 GPU 工作。默认部署已选定为原始 Qwen3-VL 教师建库、公开 ML 学生 GPU BF16 查询；CPU FP32 用于无 GPU 快速体验。当前是本地 `0.1.0rc1` 候选，尚未上传代码、权重或 Release。GPU 建库、五领域完整神经检索评测和恢复验证等待用户通知及新的计算预算。

## 安装与 CPU 快速体验

首轮验证系统为 Ubuntu／WSL、Python 3.10。使用已有源码目录，或解压本地源码包；当前没有可宣称已发布的 PyPI 或 Release 下载地址。

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install '.[demo]'
python -m pip check
# 只获取固定 ML 学生完整包，不下载教师。
python -c "from huggingface_hub import snapshot_download; snapshot_download('nanovdr/NanoVDR-Q-DistilBERT-Qwen3VL2B-2048-ML', revision='ab3f0fde9fcf407eaa756e1fc349ac09b7a716e7')"
```

将候选 `demo-bundle.zip` 解压到任意目录，在其中执行：

```bash
CUDA_VISIBLE_DEVICES= HF_HUB_OFFLINE=1 foliorecall serve \
  --index . --config configs/baseline.json --query-config configs/student-ml-cpu.json
# 单次命令行查询；每次命令都会重新加载学生。
CUDA_VISIBLE_DEVICES= HF_HUB_OFFLINE=1 foliorecall query \
  --index . --config configs/baseline.json --query-config configs/student-ml-cpu.json \
  'Which figure compares projections of the EU working-age population under baseline and no-migration scenarios?' --json
```

浏览器访问 `http://127.0.0.1:7860`。演示常驻一个模型与页面库，修改配置后重启。提供 Top-k、页码、来源、预览和 JSON 下载；相关性分数不表示回答正确概率，也没有经过校准的无答案拒答阈值。没有上传建库、多用户或公网托管功能。

包内保留骨干、配套 tokenizer、pooling、两层投影与 Normalize。42 页示例从原45页库中剔除人口报告物理第1、6、14页的已知第三方图片后复用向量；原物理页码不重编号，旧45页结果不代表新示例结果。来源与素材许可见包内 `SOURCES.md`；完整人口报告 PDF 不随包分发，公开上传前还需核对最终素材。

本机隔离验证使用 `/mnt/d/foliorecall_cache/envs/stage4_cpu`，独立缓存为 `/mnt/d/foliorecall_cache/stage4_cpu/huggingface`，移动后的示例在 `/mnt/d/foliorecall_cache/stage4_cpu/moved example`。这些是本机验证位置，不是其他使用者必须采用的路径。

## GPU 自有 PDF 路径：本轮待验证

保留既有 GPU 环境；新环境安装与硬件条件需在用户安排 GPU 工作后完成验证。现有已验证核心环境为 torch 2.8.0+cu126、torchvision 0.23.0+cu126，页面编码使用原始教师 BF16、batch1、固定像素预算。页面建库依赖 `foliorecall[image]`，训练另加 `[train]`，评测另加 `[eval]`。

```bash
# 在已准备的 GPU 环境及源码目录中：
python scripts/prepare_data.py model
foliorecall import /path/to/your.pdf --output /path/to/new-pages
foliorecall index --config configs/baseline.json \
  --pages /path/to/new-pages/pages.jsonl --output /path/to/new-index
# 用户选定的默认演示配置：
foliorecall serve --config configs/baseline.json --query-config configs/student-ml-cuda.json \
  --index /path/to/new-index
# 同一原始教师页面库也可以改用 student-ml-cpu.json。
```

CPU 快速查询不意味着任意自有 PDF 可以低成本 CPU 建库。输入文件或 DPI 变化时使用新的导入和索引目录，防止旧向量继续引用已改写的页面图像。损坏或加密文件写入导入错误记录，正常文件继续处理。无 GPU 时不会把教师页面计算改到 CPU 自动执行。

## 固定外部评测与方法对照

### GPU接续与恢复（rc2）

rc2的建库、恢复保护及统计代码已完成相关CPU测试；实际GPU建库、恢复和安装使用仍待用户通知资源时段。10小时为独立累计上限，常规任务保留最后1小时。源码检出继续记录提交与差异；新GPU安装环境仅用于安装态使用验证，不替换已有训练或CPU环境。

```bash
# 只生成配置副本与固定任务清单，不加载模型：
python scripts/prepare_stage4_remaining.py
# 输出 remaining-preparation/jobs.json：9个建库、25个GPU评测、12个新增CPU评测。
# --resume只用于同一未完成输出；暂停返回75，正式索引尚不存在。
foliorecall index --config configs/baseline.json --pages <pages.jsonl> \
  --output <new-index> --chunk-size 64 --max-seconds 600
foliorecall index --config configs/baseline.json --pages <pages.jsonl> \
  --output <new-index> --chunk-size 64 --max-seconds 600 --resume
```

工作缓存位于 `<new-index>.work`，只有完整索引才出现在 `<new-index>`。输入、教师、batch、设备或清单顺序变化时使用新目录。任务中断后先查看缓存记录，不删除原块或修改页面配置迁就缓存；该接口实际GPU恢复仍待验证。

用户确认GPU空闲后，从任务清单取完整命令，使用 `python scripts/run_stage4_gpu.py <新运行名> --gpu-available --max-seconds <本任务秒数> --command <完整命令>`。该脚本检查已有GPU计算进程，串行持有预算锁，累计记录子进程耗时；不沿用阶段三账本。每域首块64页校准页速，下一完整领域的预计建库与评测时间加25%余量必须低于扣除1小时预留后的余额；不满足则停止新领域。`--use-reserve`仅供最后验收或必要故障处理。未确认资源时段不要传 `--gpu-available`。

学生恢复试验使用新目录和同一64条目标，两组都固定 `--max-steps 4 --limit 64 --skip-evaluation`；连续组跑4步，另一组加 `--stop-after 2`，然后从自身 `checkpoint-2` 恢复到4步，不更改总训练步数或调度。正式阶段三检查点不写入。已完成训练、回退到旧检查点或缺少优化器状态会提前拒绝。

完整矩阵汇总命令为 `python scripts/summarize_stage4.py --matrix outputs/stage4/remaining-preparation/jobs.json --output <新汇总目录>`。未执行任务显示待验证；只有五域齐全的候选生成宏平均和配对重采样区间。LoRA适配器、加载/预热显存、暖态显存和部署索引体积分开统计，旧HR缺失的建库分项不补造。

任务与 revision 固定于 [评测配置](../configs/stage4-evaluation.json)。五领域为 HR、Computer Science、Finance-EN、Industrial、Pharmaceuticals，共12969页、1489条英文查询。保留完整候选库和分级、多正例标签。正式结果逐任务报告 nDCG@10、Recall@5/10，再计算任务宏平均；不按分数选择任务或修改标签。

```bash
python -m pip install '.[eval]'
# 数据准备无需模型；复用 HR 缓存，其他任务只下载必要 Parquet。
CUDA_VISIBLE_DEVICES= python scripts/prepare_stage4_data.py
# 可用 --task hr 等只接续某个固定任务。
CUDA_VISIBLE_DEVICES= python -m foliorecall evaluate-text --config configs/stage4-evaluation.json \
  --data outputs/stage4/data/hr --output /path/to/new-bm25-run
# 复用已有完整 HR 原始教师库；其他四域神经检索需等待 GPU 页面索引。
CUDA_VISIBLE_DEVICES= python -m foliorecall evaluate --config configs/baseline.json \
  --query-config configs/student-ml-cpu.json --index indexes/hr-original \
  --data outputs/stage4/data/hr --output /path/to/new-hr-run --benchmark
```

BM25 是上游页面 markdown 文本对照，固定 `rank-bm25==0.2.2` 的 Okapi 默认参数。页面与查询统一 NFKC、casefold、Unicode 单词分词，保留数字，不做 OCR、分块、停用词过滤或调参。空文本页仍保留，并报告文本覆盖率；上游 OCR 成本未知，不能把它列作零成本。

排名保留原始分数，同分按页面 ID 字符串降序；Top-k 边界需补齐同分候选。指标使用线性相关性等级，与 `pytrec-eval-terrier==0.5.10` 对照验证。新排序约定的代码版本与历史运行分别记录，不回写阶段三结果。

正式 GPU 候选固定为原始教师、LoRA750、公开 EN、公开 ML、蒸馏第94步；CPU 对照为三款学生。LoRA使用自身编码的完整页面库，其余四组使用原始教师页面库；不为LoRA再训练学生，也不借外部结果重新挑339／750或94／188／282。阶段二教师、训练记录与阶段三完整学生包入口见 [README](../README.md#第二阶段接续) 及 [查询学生与蒸馏说明](查询学生与蒸馏.md)。

HR 的20条查询此前用于流程检查，不能把完整318条都称为从未接触；另外四域不参与调参。规范化训练查询交集按任务写入数据来源记录，发现交集仍保留官方任务并单独披露。原始文档隔离和公开学生上游训练重叠仍未完全核实。

## 测量与产物

模型配置在独立进程中以 batch1、PyTorch线程4、FAISS线程1、预热5次及固定顺序3轮测量。分词与编码、编码加搜索、文本至结果JSON就绪分别报告P50/P95；模型加载和整个进程耗时另计，保留每次请求与每轮摘要。BM25没有神经编码，报告文本分词、评分加排序及JSON就绪时间。

应用回调另计页面读取与显示准备，Gradio处理、响应传输和浏览器渲染不能混入模型编码加速比。只有同硬件同精度的GPU教师/学生可计算编码加速；CPU单列为部署方案。记录预热RSS、整个进程峰值RSS、权重和索引体积；GPU步骤执行后再补分配与保留显存、页面编码吞吐和完整建库分项。

新产物集中在 `outputs/stage4`：`data`为固定任务，`demo-bundle`为示例，`packages`为安装产物，`runs`保存CPU任务命令、日志和整个子进程耗时。关键运行另保留实际提交、生效配置和影响结果的未提交差异。已存在结果使用新运行名或新目录，不覆盖。

### 安装与相关验证证据
