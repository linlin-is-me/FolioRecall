## 安装与 CPU 快速体验

首轮验证系统为 Ubuntu／WSL、Python 3.10。使用已有源码目录，或解压本地源码包；当前没有可宣称已发布的 PyPI 或 Release 下载地址。

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install '.[demo]'
python -m pip check
# 只获取固定 ML 学生完整包，不下载教师。
python -c "from huggingface_hub import snapshot_download; snapshot_download('nanovdr/NanoVDR-Q-DistilBERT-Qwen3VL2B-2048-ML', revision='ab3f0fde9fcf407eaa756e1fc349ac09b7a716e7')"
```

将候选 `demo-bundle.zip` 解压到任意目录，在其中执行：

```bash
CUDA_VISIBLE_DEVICES= HF_HUB_OFFLINE=1 foliorecall serve \
  --index . --config configs/baseline.json --query-config configs/student-ml-cpu.json
# 单次命令行查询；每次命令都会重新加载学生。
CUDA_VISIBLE_DEVICES= HF_HUB_OFFLINE=1 foliorecall query \
  --index . --config configs/baseline.json --query-config configs/student-ml-cpu.json \
  'Which figure compares projections of the EU working-age population under baseline and no-migration scenarios?' --json
```

浏览器访问 `http://127.0.0.1:7860`。演示常驻一个模型与页面库，修改配置后重启。提供 Top-k、页码、来源、预览和 JSON 下载；相关性分数不表示回答正确概率，也没有经过校准的无答案拒答阈值。没有上传建库、多用户或公网托管功能。

包内保留骨干、配套 tokenizer、pooling、两层投影与 Normalize。42 页示例从原45页库中剔除人口报告物理第1、6、14页的已知第三方图片后复用向量；原物理页码不重编号，旧45页结果不代表新示例结果。来源与素材许可见包内 `SOURCES.md`；完整人口报告 PDF 不随包分发，最终本地素材核对已通过，见 `outputs/stage4/release-materials-final`；公开上传仍待授权。

## 发布前复核（2026-09-13）

在提交272096b上只读核对了40组保存结果的任务数量、5次预热、3轮、PyTorch/FAISS线程4/1及逐请求数量，全部一致，10套页面库均有完整索引。CPU安装态、45页续接、104个学生参数及优化器/调度器/RNG恢复的既有记录均存在。此次没有重新训练、GPU计算或全量回归。

发现的实际使用问题是导出LoRA配置与历史索引的路径身份不同：`model-candidates-rc2-final/lora750/encoding.json` 使用 `adapter: .`，历史HR索引的config.json使用原checkpoint-750绝对路径。`search.encoding_identity` 保留adapter字段，`load_index` 比较原始配置，因此在导出目录执行下列命令会于模型加载前失败：

```bash
CUDA_VISIBLE_DEVICES= HF_HUB_OFFLINE=1 foliorecall query --config encoding.json \
  --index /mnt/d/myproject/FolioRecall/outputs/stage4/indexes/hr/lora750 \
  'What are the main employment and social trends?' --json
# FolioRecall: ValueError: 查询编码配置与索引不匹配，请使用同一模型、适配器与预处理配置
```

该复现使用22a209a构建的最终wheel和CPU隔离环境，没有加载教师。`validate_exported_models_gpu.py` 先用历史索引自身配置读库，再单独加载导出模型比较两张页面的向量，未将导出配置传入完整检索装配，因此此前GPU向量相等不能覆盖此命令的可用性。导出包自身模型卡要求用该包配置新建库，和使用说明直接复用历史库的写法不一致。正式评测使用原配置，指标不受此问题影响。

建议先明确两条支持路径：历史实验库使用原匹配配置；导出包使用与其配置配套的索引。若要支持同权重搬移后直接复用旧库，必须区分稳定模型身份与文件位置，或提供经过验证的显式迁移；不能简单忽略adapter字段，也无需为修正文档重建五域索引。相关修改后补配置提前校验和实际CLI检查。
