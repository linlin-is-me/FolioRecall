# FolioRecall 0.1.0：本地候选快速开始

已验证 Python 3.10、Ubuntu 22.04／WSL 2。本候选尚未发布，附件由本地审核目录提供。
界面默认采用白色卡片、浅灰背景和绿色强调色，不随系统深色偏好自动变暗；排版和交互不变。
默认使用六层 ONNX FP32 查询学生，无需 GPU、教师权重或重新建库。
The local candidate includes a 42-page demo and separate ONNX model assets. Public downloads are pending review.

## 安装与解压

在附件目录执行。已有相同依赖环境可复用，首次安装需要下载 Python 依赖：

```bash
python3.10 -m venv .venv
CPU_PY="$PWD/.venv/bin/python"
"$CPU_PY" -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
"$CPU_PY" -m pip install 'foliorecall-0.1.0-py3-none-any.whl[onnx,demo,agent,multiagent]'
"$CPU_PY" -m zipfile -e demo-bundle.zip demo-local
"$CPU_PY" -m zipfile -e query-onnx-fp32.zip demo-local
cd demo-local/demo-bundle
```

复用已安装旧 `0.1.0` 的环境时，先用上述 extras 命令补齐依赖，再从附件目录执行
`"$CPU_PY" -m pip install --force-reinstall --no-deps foliorecall-0.1.0-py3-none-any.whl`。
`CPU_PY` 使用绝对路径，切换目录后仍可使用。

```text
demo-local/
├── demo-bundle/        # 此目录执行下列命令
│   ├── configs/
│   ├── previews/
│   └── text-index/     # 另有页面清单、FAISS 索引和正文
├── query-models/
│   ├── onnx-fp32/
│   └── onnx-int8/      # 可选
└── outputs/            # 首次需要时创建
```

模型路径相对当前工作目录解析；FP32 配置为 `../query-models/onnx-fp32`。
42 页示例不含完整 PDF，模型附件保留上游许可与来源。

## 免费检索

```bash
CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall query --index . \
  --config configs/baseline.json --query-config configs/student-ml-cpu-default.json \
  --retrieval-config hybrid.json \
  'Which figure compares projections of the EU working-age population under baseline and no-migration scenarios?' --json

CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall serve --index . \
  --config configs/baseline.json --query-config configs/student-ml-cpu-default.json \
  --retrieval-config hybrid.json --port 7867
```

打开 http://127.0.0.1:7867，页面检索为默认页。顶部显示当前文档库，点击示例填入问题，再提交检索。来源显示简称与物理页码，结果明细及 JSON 保留完整文件名。
模型和索引常驻。省略 `--retrieval-config hybrid.json` 即使用视觉检索。
检索不需要生成 API，ONNX 启动使用附件模型，不临时导出或下载学生。

## RAG、Agent 与追问

停止免费检索服务，配置北京百炼密钥后启动：

```bash
export DASHSCOPE_API_KEY='replace-with-your-key'
export DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
RUN_DIR="../outputs/chat-$(date +%Y%m%d-%H%M%S)"
CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall serve --index . \
  --config configs/baseline.json --query-config configs/student-ml-cpu-default.json \
  --retrieval-config hybrid.json --agent-config configs/agent-demo.json \
  --public-corpus public-corpus.json --output "$RUN_DIR" --port 7867
```

启用生成服务后默认打开文档问答页。首问示例直接可见，点击只填写问题，保留当前回答模式，不会自动提交或产生调用费用。也可自行输入英文或中文问题。
首问完成后，展开追问与更多示例继续提问；依赖上文的问题与需要新建会话的问题分别标注。跨主题时点击新建会话。
引用使用文件名生成的简短显示名；悬停或展开原页可查看完整文件名，保存的 JSON 与引用 ID 不变。
实时步骤显示实际搜索、读页和模型请求，引用跳转到原页，展开区可复制最终 JSON。
记录写入新目录，避免重复使用已有输出目录。需要再次启动时重新设置 `RUN_DIR`。

模型为 `qwen3.7-plus-2026-05-26`，关闭思考，温度 0；问题、检索摘要及读取的公开页面图像和正文会发送到百炼。
问答需要自行配置密钥并保证服务账户余额。示例预算 20 元是支出上限，非赠送余额。
费用账本在配置中为 `../outputs/api-costs.sqlite3`，相对配置目录解析，实际位于 `demo-bundle/outputs`；新建会话不会清空费用。
只使用最近三轮成功问答理解指代，本轮引用仍需本轮实际读页。

## 文档研究：职责、依赖与核验返工

在同一示例目录启动，研究模式是本轮工程展示入口；质量对照没有证明它整体优于单Agent，日常快速问答仍可选择Agent。

```bash
RUN_DIR="../outputs/research-$(date +%Y%m%d-%H%M%S)"
CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall serve --index . \
  --config configs/baseline.json --query-config configs/student-ml-cpu-default.json \
  --retrieval-config hybrid.json --agent-config configs/agent-demo.json \
  --multi-agent-config configs/agent-research-demo.json \
  --public-corpus public-corpus.json --output "$RUN_DIR" --port 7867
```

界面默认选择文档研究，点击首问、追问或新会话示例均保留该模式；切换RAG或单Agent需要手动选择。规划协调、最多两位责任不同的取证Agent、分析与核验共用资源。依赖任务等待前置完成；核验后最多一次取证或分析返工。每轮16请求、6搜索、10页、16000输出tokens、300秒，最多两路远程请求并发，本地检索串行。

可尝试询问人口与就业报告如何描述欧盟变化，再用中文追问证据页与时间范围。首次与末次核验分开显示，核验不是人工确认；也可能遗漏、误删或返回结构失败。[60次真实结果与局限](首版使用与评测.md#multi-agent-research-results)。单Agent配置和旧basic配置均保留，省略 `collaboration_workflow` 时仍走basic。

## 原basic协作（可选）

默认仍使用原RAG或单Agent。需要协调器拆分与最多两个检索Agent时，安装可选依赖：

```bash
"$CPU_PY" -m pip install langgraph==1.2.15 langgraph-checkpoint-sqlite==3.1.2
RUN_DIR="../outputs/multi-$(date +%Y%m%d-%H%M%S)"
CUDA_VISIBLE_DEVICES= "$CPU_PY" -m foliorecall serve --index . \
  --config configs/baseline.json --query-config configs/student-ml-cpu-default.json \
  --retrieval-config hybrid.json --agent-config configs/agent-demo.json \
  --multi-agent-config configs/agent-multi-demo.json \
  --public-corpus public-corpus.json --output "$RUN_DIR" --port 7867
```

在问答页选择 `multi-agent`。执行步骤显示协调器及检索Agent，来源图像和最终JSON沿用原界面。协作每轮共用12次请求、4次搜索、8页、12000输出tokens和240秒活动时间；协调器可只拆出一个子任务。新建会话清空历史，费用仍累计到同一账本。

CLI使用 `ask --mode multi-agent`，并提供原有索引、查询配置、混合检索配置、公开语料和协作生成配置。需要恢复时沿用同一任务输出目录加 `--resume`；已完成任务直接读取原结果，成功响应不重复调用，状态不明的在途请求暂停处理。浏览器暂不提供恢复按钮。

协作质量、费用和真实使用记录见源码中的使用与评测文档；可选模式不表示整体优于单Agent。

## 切换后端与边界

- int8：回到附件目录，解压 `query-onnx-int8.zip` 到同一 `demo-local`，再回到 `demo-local/demo-bundle`，将查询配置改为 `configs/student-ml-onnx-int8.json`。速度与质量存在取舍，本机 VNNI 结果不保证其他 CPU 同等收益。
- PyTorch：将查询配置改为 `configs/student-ml-cpu.json`。需要指定的上游公开学生或已有缓存，首次可能下载模型；这一选择不使用 ONNX 附件。
- 缺省后端字段的旧配置继续使用 PyTorch。公开 CLI、API 和答案三字段结构保持兼容。
- 功能检查复用依赖环境，不代表全新机器安装；原默认组合曾使用模拟生成器检查装配；本次协作候选另完成六次真实安装态浏览器确认与三组开发对照，质量仍为助手评分。
- 本地单用户，会话刷新清空；可能遗漏来源或误读图表，助手评分保持 `human=not_checked`。

素材见示例 `SOURCES.md`，模型见各包 `UPSTREAM.md` 与 `LICENSE`。完整使用、实验与项目介绍见源码包的 README 和 doc 目录。
