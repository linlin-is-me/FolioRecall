## 阶段三：蒸馏查询模型并降低在线成本

```text
请开始或接续 FolioRecall 第三阶段，完成查询学生蒸馏，比较质量与在线成本，选择可部署的教师与学生组合。

本轮重点：[可选；未指定则根据实际状态选择下一项任务]

先读取 AGENTS.md、README、开发计划第 1 节，以及查询蒸馏和评测相关章节。查看第二阶段结论，定位选定教师、编码配置和可复用结果；教师可以是原始模型或微调模型，不预设微调版本一定更好。

围绕以下目标推进：
1. 按计划比较适用的公开查询学生。公开学生使用其对应原始教师的页面索引，不把向量空间尚未对齐的组合当作正常竞品基线。
2. 用选定教师生成并缓存训练查询向量，优先采用计划中的轻量初始化与对齐目标，完成小规模蒸馏，再依据检索结果决定是否扩大查询数据或训练量。
3. 在匹配的页面索引上比较教师与学生，测量检索质量、查询编码与完整请求延迟、内存或显存。蒸馏损失仅用于诊断，不替代实际检索指标；测量条件保持可解释。
4. 如果教师提升未在学生端保留，先排查表示空间、预处理及数据覆盖，再决定是否补充少量候选实验。不为每个教师检查点预先训练一遍学生，不强求每项改动都保留。

查询编码保持独立入口，将骨干、tokenizer、投影层和必要配置成套加载。为后续多深度学生、ONNX/int8 或中文学生保留可替换位置，只实现本轮需要的方案。保持教师空间不变时，切换已对齐的查询学生可复用页面索引；教师或页面编码设置改变时，再更新相关表示和索引。

优化以计时和错误案例为依据。查询编码确实构成瓶颈时再试部署优化或学生结构调整，不预建动态路由与多模型并发管理。区分同硬件下的编码加速与 CPU/GPU 不同部署方案的成本比较，计入完整请求中实际启用的处理。

采用小规模试验和相关验证，按实际改动创建本地提交；记录既有证据，不额外安排全量回归或哈希核验。远程操作沿用已有授权范围。关键实验按 AGENTS.md 关联实际运行的代码版本、生效配置与产物位置，注明影响结果的未提交改动。

结束时报告质量与成本取舍、验证情况和提交情况，并在进展变化时更新开发计划第 1 节。交接引用最终或当前候选的教师、学生、tokenizer、投影、页面索引及配置位置，给出可用的加载和查询命令入口。README 只声明实测支持的能力。明确第四阶段还需补哪些结果与使用流程；若蒸馏尚未完成，留下当前阻塞和下一项具体工作。

上述进度与说明更新完成后，将本轮应保存的文档改动纳入相关提交。结束前按 AGENTS.md 查看 Git 状态，在回复中报告当前分支、最新提交、需接续的未提交内容及远程同步状态；保留用户原有改动，不要求清空工作区。
```
